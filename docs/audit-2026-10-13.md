## Reproduced defects

P1 means a security boundary, crash, leak or cost-control defect deserving prompt attention. P2 means a reproducible functional or build defect. The dependency scanner findings describe reachable vulnerable symbols, not demonstrated exploits against a running deployment.

### F01 — P1: requests can inherit another account or token's permissions

Original locations: [server/server_auth.go:31](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_auth.go#L31), [server/visitor.go:376](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/visitor.go#L376), [server/server_account.go:102](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_account.go#L102), [server/server_ai.go:47](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_ai.go#L47).

Authentication writes the user into a shared visitor/rate-limit bucket. Handlers later read the bucket's mutable user. Free accounts share an IP bucket; credentials for a paid account also share its account bucket. Locking individual getters does not prevent one request's identity from changing between authentication and authorization.

Deterministic reproduction: authenticate Alice, then Bob from the same IP, then finish Alice's account request. It returns Bob. The same interleaving turns an anonymous account request into Alice, allows a device token to reach `/v1/users`, and allows a read-only token through `ensureAIScope` after another request authenticates with a password. These are logical races even when no Go memory race is reported.

Fix: [#42](https://github.com/mptfire/axon/pull/42) stores the principal, including anonymous nil, in request context and uses it for account, topic and scope authorization, message/web-push attribution, AI budgets and asynchronous account sync. Rate-limit bucket grouping stays unchanged. Tests: `TestServer_Authentication_RequestKeepsItsAccount`, `DeviceScopeSurvivesOtherRequest`, `AnonymousRequestStaysAnonymous`, `AIScopeSurvivesOtherRequest` (all under the `TestServer_Authentication_` prefix). An anonymous token-update guard and regression also cover upstream's missing nil-user fix.

### F02 — P1: scoped tokens can fetch or mint unrestricted credentials

Original locations: [server/server_account.go:76](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_account.go#L76), [server/server_account.go:167](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_account.go#L167), [server/server_account.go:297](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_account.go#L297).

Only device tokens have their account token values stripped. Other scoped agents can GET `/v1/account` to retrieve unrestricted tokens, or POST `/v1/account/token` to mint one. A token without `ai` can then invoke AI features using the unrestricted credential. Login, pairing and admin management expose additional escalation paths. This reproduction needs no concurrent requests.

Fix: [#43](https://github.com/mptfire/axon/pull/43) blocks account/token, device, billing and admin management for scoped agents and strips token values from their account responses. Read-only account metadata remains available to `list_subscriptions`. The device sandbox remains separate. The `read` and `publish` labels still do not independently gate ordinary message capabilities; topic ACLs do. The CLI and docs now state that accurately and describe budgets as account-based. `TestServer_ScopedToken_CannotEscalate` checks read/publish/ai tokens owned by an admin, four escalation routes, and account credential omission. Before the fix token creation succeeds and account GET exposes token values.

### F03 — P1: private digest history is public under public default ACLs

Original location: [server/server_digest.go:190](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_digest.go#L190).

Granting the owner read access does not deny the server's default read/write access to others. If the generated topic name is learned, anonymous callers or another user can read aggregated private history and publish a forged briefing. Topic-name entropy is not an authorization check.

Fix: [#38](https://github.com/mptfire/axon/pull/38) denies Everyone before granting the owner. It also repairs already provisioned `dg_` digest topics before listening, including when schedules or AI are disabled, and fails closed if that repair fails. The startup addition fixes a residual gap reproduced against the first revision of this PR: an old owner-only ACL remained public indefinitely when there was no future delivery to repair it.

Tests: `TestServer_AI_DigestDelivery_PrivateWithOpenDefault` checks anonymous/other-user reads, anonymous writes, owner reads and ordinary public publishing. `TestServer_AI_DigestDelivery_HardensExistingTopicsWhenAIDisabled` restarts against a legacy ACL: anonymous GET changes from 200 to 403; owner access and an ordinary public topic still work.

### F04 — P1: concurrent AI calls can all pass an exhausted budget

Original locations: [ai/ai.go:123](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/ai.go#L123), [ai/budget.go:51](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/budget.go#L51).

`Allow` checks completed usage, then the provider call runs outside the lock, then `Record` charges it. Calls in flight are invisible. A blocked first call and a second call both reach the provider; the second eventually returns a context deadline rather than the expected budget rejection. Negative usage and integer overflow can also reopen an exhausted budget.

Fix: [#39](https://github.com/mptfire/axon/pull/39) reserves estimated input plus maximum output atomically before provider work, settles once, preserves outstanding reservations through midnight, clamps negative counters and saturates sums. Tests cover concurrent calls, negative/overflow usage, midnight rollover and duplicate settlement. Reservations use input estimates, so they are not an exact billing cap for every tokenizer or provider.

### F05 — P1: embeddings and inline enrichment bypass visitor cost accounting

Original locations: [ai/ai.go:176](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/ai.go#L176), [server/server_ai.go:105](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_ai.go#L105), [ai/enrich.go](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/enrich.go).

Embedding work has no token-budget gate/accounting or client deadline. Inline enrichment uses no publisher attribution key; the publisher's report stays at zero requests despite enrichment. Free authenticated accounts are otherwise attributed by IP, which also disagrees with the scheduler's account key.

Fix: [#39](https://github.com/mptfire/axon/pull/39) meters embeddings with provider usage when available, estimates otherwise, honors context/timeouts, and threads account/publisher identity through enrichment, chat retrieval and digest clustering. Tests: `TestEmbedder_CallsCannotBypassBudget`, `TestEmbedder_ChargesProviderReportedUsage`, `TestServer_AI_Enrichment_AttributesPublisherUsage`. The publisher reproduction changes from zero to one attributed request. [#42](https://github.com/mptfire/axon/pull/42) then makes that attribution use the request principal consistently.

### F06 — P1: checkout limiter can crash the server with AI disabled

Original location: [server/server_payments.go:194](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_payments.go#L194).

The fork adds a shared IP→attempts map but never locks its declared mutex in `checkoutSuccessAllowed`. Concurrent requests to the unauthenticated Stripe checkout-success endpoint race on the map and backing slices. The new 32-caller test reports data races and crashes with `fatal error: concurrent map read and map write`. This is a fork regression independent of AI being enabled.

Fix: [#44](https://github.com/mptfire/axon/pull/44) locks the entire check/update, periodically reaps inactive IP entries, and isolates the existing sequential test's state for repeated runs. `TestCheckoutSuccessLimiterConcurrent` admits exactly ten callers; the cleanup and existing sliding-window tests pass three consecutive runs under `-race`.

### F07 — P2: concurrent device claims exceed the ten-device quota

Original location: [user/manager_device.go:237](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/user/manager_device.go#L237).

Build-key claims count devices before opening the insert transaction. Starting with nine devices, concurrent calls reproduced eleven registered devices against a maximum of ten. Distinct pairing codes also lack a common owner lock on PostgreSQL.

Fix: [#45](https://github.com/mptfire/axon/pull/45) locks the owner row, checks the count, and inserts the device/token in one transaction. The shared database gate covers multiple managers/processes and both claim paths; no migration is needed. `TestManager_DeviceQuotaConcurrent` races 32 callers through two managers for both build-key and distinct pairing-code claims, requires exactly ten devices, and rejects unexpected database errors. SQLite passes three race-enabled runs. The same test covers PostgreSQL in GitHub CI.

### F08 — P2: MCP wait returns the stream-opening event and times out early

Original locations: [mcp/tools.go:259](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/mcp/tools.go#L259), [mcp/tools.go:313](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/mcp/tools.go#L313), [mcp/mcp.go:38](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/mcp/mcp.go#L38).

Open/keepalive events have IDs; checking only for an ID returns the initial `open` event as the reply. Separately, the ordinary 15-second HTTP client timeout overrides the default 60-second or maximum 300-second wait. The accelerated timeout reproduction fails while reading before a scripted reply arrives.

Fix: [#35](https://github.com/mptfire/axon/pull/35) filters by `event == message` in wait/read and uses a copied client with no ordinary timeout for waits; the wait context bounds it. Tests: `TestToolSubscribeWait_IgnoresControlEventsWithIDs`, `TestToolSubscribeWait_UsesWaitDeadlineNotClientTimeout`.

### F09 — P2: all six strict structured-output schemas violate provider requirements

Original locations: [ai/planner_prompt.go:15](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/planner_prompt.go#L15), [ai/enrich.go:22](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/enrich.go#L22), [ai/chat.go:24](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/chat.go#L24); digest/briefing schemas have the same defect.

The OpenAI adapter sends `strict: true`, but object schemas omit `additionalProperties: false` and list only some properties in `required`. This violates the [provider's structured-output contract](https://developers.openai.com/api/docs/guides/structured-outputs), including for nested array-item objects. `TestFeatureSchemas_StrictOutputContract` fails across all six feature schemas.

Fix: [#36](https://github.com/mptfire/axon/pull/36) makes every object conform and updates prompts to emit empty values for unused fields. No paid/live provider call was made; validation is through the documented contract and scripted provider tests.

### F10 — P2: malformed plan JSON can panic; translation ignores opt-in

Original locations: [ai/planner.go:166](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/planner.go#L166), [ai/enrich.go:125](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/enrich.go#L125).

`{"subscriptions":[null]}` unmarshals into a nil pointer and panics when the planner reads its topic. An unsolicited model translation is also returned even when `TranslateTo` is empty, allowing a provider response to change the published message without translation being requested.

Fix: [#36](https://github.com/mptfire/axon/pull/36) rejects null plan elements and discards translation unless requested. Tests: `TestPlanner_RejectsNullSubscription` and `TestEnrich_TranslationRequiresOptIn`.

### F11 — P1/P2: AI streams leak on cancellation and ignore the client deadline

Original locations: [ai/stream.go:27](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/stream.go#L27), [ai/stream.go:57](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/stream.go#L57), [ai/openai.go:220](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/openai.go#L220).

The client does not apply its configured timeout to streaming work. Unconditional channel sends remain blocked when the consumer exits, even after cancellation. The cancellation regression observes a client goroutine still blocked after one second; the deadline regression outlives the configured bound.

Fix: [#37](https://github.com/mptfire/axon/pull/37) applies a deadline, makes sends cancellation-safe, closes provider bodies and cancels HTTP chat work on every return. The web dialog aborts on unmount and releases/cancels its reader. Tests: `TestCompleteStream_DeadlineBoundsProvider`, `TestCompleteStream_CancellationReleasesUndrainedOutput`.

### F12 — P2: malformed/truncated streams are reported as success; usage is undercounted

Original locations: [ai/openai.go:220](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/openai.go#L220), [ai/stream.go:60](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/ai/stream.go#L60).

Malformed SSE chunks and scanner failures are ignored; EOF without a completion marker can look successful. Input tokens are always zero. Rounding each tiny delta independently makes one-byte chunks free, and partial failures avoid the final accounting path.

Fix: [#37](https://github.com/mptfire/axon/pull/37) propagates malformed/scanner/truncation errors, requires a completion marker, requests OpenAI stream usage, carries provider usage through events and counts aggregate fallback text plus input. It accounts for partial failures, bounds stream output to 64 KiB and HTTP chat answers to 4000 runes, and preserves an explicit zero temperature. [#39](https://github.com/mptfire/axon/pull/39) adds reservations. Tests: `TestOpenAIStream_RejectsMalformedOrTruncatedSSE`, `TestCompleteStream_TinyChunksStillChargeInputAndOutput`.

### F13 — P2: cross-topic web chat sends an invalid request and accepts incomplete answers

Original locations: [web/src/app/AiApi.js:41](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/web/src/app/AiApi.js#L41), [web/src/components/AiChatDialog.jsx:54](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/web/src/components/AiChatDialog.jsx#L54).

The client sends both `all: true` and `topic`, which the server rejects. It also accepts EOF without `done` and ignores an SSE error after partial output. Three new web regressions fail before the fix.

Fix: [#37](https://github.com/mptfire/axon/pull/37) omits the topic for cross-topic requests, requires `done`, surfaces errors, cancels/releases the reader, and removes the stale closure fallback for answer text. The corresponding tests are in `web/src/app/AiApi.test.js`.

### F14 — P2: AI-configured subscription priority is saved but not applied

### F17 — P2 documentation: template deadline claim exceeds what the patch guarantees

Locations: [template/gotext/exec.go:314](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/template/gotext/exec.go#L314), [server/server_template.go:139](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/server/server_template.go#L139), [template/gotext/README.md](https://github.com/mptfire/axon/blob/67be809f8a77b7505ad1d169633f06ad8a940e79/template/gotext/README.md).

The vendored interpreter checks context between execution steps; it cannot interrupt an arbitrary blocking helper inside a step. The server separately caps template input at 32 KiB and output at 1 MiB and guards printf amplification and other helpers. These are useful bounds, but they are not a process-wide memory limit or unconditional function preemption.

[#40](https://github.com/mptfire/axon/pull/40) corrects the README claim and refreshes Go 1.27.2 provenance. `template-check` verifies the generated source plus patch; the server's template and AI-disabled regressions pass under `-race`. This finding is a documentation guarantee correction, not a demonstrated new template exploit.
